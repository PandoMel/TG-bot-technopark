# TG-bot-propusk

Telegram-бот для регистрации сотрудников, заказа пропусков и управления доступом через основную Telegram-группу.

## Структура проекта

```text
TG-bot-propusk/
├── bot.py                    # Точка входа, middleware, роутеры и фоновые задачи
├── config.py                 # Токен, ID чатов, пути и настройки
├── database.py               # Legacy-хранилище bd.txt и in-memory кэш
├── services.py               # Бизнес-логика, JSON участников, работа с регистрацией
├── access_control.py         # Проверка членства, прав администратора и синхронизация
├── middlewares.py            # Общая защита личного чата и админских действий
├── logging_module.py         # Настройка и ротация логов
├── keyboards.py              # Inline- и Reply-клавиатуры
├── FSMstates.py              # FSM-состояния основных сценариев
├── html_export.py            # HTML-журнал пропусков
├── routers/
│   ├── user.py               # Регистрация, пропуска и заявки на ремонт
│   ├── admin.py              # Legacy-функции админки и просмотр логов
│   ├── admin_users.py        # Профиль, сообщения и редактирование пользователя
│   ├── admin_cleanup.py      # Удаление/блокировка вместе с регистрацией
│   ├── events.py             # События вступления, выхода и исключения
│   └── fallback.py           # Обработка неактуальных кнопок и неверного ввода
├── bd.txt                    # ID;Компания + ФИО;Телефон
├── group_members.json        # Текущие известные участники группы
├── bot.log                   # Технические события и аудит доступа
├── KPP.log                   # Журнал заявок на пропуск
└── UK.log                    # Журнал заявок на ремонт
```

## Требования

- Python 3.13
- aiogram 3.14.0

```bash
pip install aiogram==3.14.0
python bot.py
```

## Основные настройки

В `config.py` необходимо указать:

- `bot_token` — токен Telegram-бота;
- `CHANNEL_ID` — основная группа, членство в которой дает доступ к боту;
- `OHRANA_ID` — чат охраны для заявок на пропуск;
- `AXO_ID` — чат для заявок на ремонт.

Администраторы не задаются отдельным списком. Права проверяются динамически по статусу пользователя в `CHANNEL_ID`.

## Требования к Telegram-группе

Бот должен быть администратором `CHANNEL_ID` и иметь права:

- получать события изменения состава группы;
- удалять и блокировать участников;
- получать информацию об участниках и администраторах.

События `chat_member` используются для учета вступлений, самостоятельных выходов и исключений.

## Правила доступа

- любой входящий текст или callback в личном чате проверяется по членству в `CHANNEL_ID`;
- при отсутствии доступа пользователь получает сообщение `Доступ запрещен`;
- отказ записывается в `bot.log` как `ACCESS_DENIED`;
- административное меню и действия доступны только текущим администраторам или владельцу группы;
- попытки доступа к админке без прав записываются как `ADMIN_ACCESS_DENIED`.

## Учет пользователей

`bd.txt` остается Legacy-базой регистрации в формате:

```text
ID;Компания + ФИО;Телефон
```

`group_members.json` хранит только текущих известных участников группы. История выходов в JSON не накапливается, события остаются в `bot.log`.

При вступлении пользователь добавляется в `group_members.json`.

При самостоятельном выходе, удалении или блокировке пользователя:

1. запись удаляется из `group_members.json`;
2. регистрация удаляется из `bd.txt`;
3. событие и причина записываются в `bot.log`;
4. текущие администраторы группы получают уведомление.

При запуске выполняется синхронизация известных ID из `bd.txt`, `group_members.json` и списка администраторов. Полный список неизвестных участников Telegram Bot API не предоставляет.

## Админка

В профиле пользователя доступны:

- Telegram ID и ссылка `tg://user?id=...`, работающая без username;
- данные из `bd.txt`;
- статус в группе;
- последние заявки на пропуск;
- отправка личного сообщения;
- изменение компании, ФИО и телефона;
- удаление из группы;
- блокировка и разблокировка;
- отдельное удаление регистрации.

Удаление и блокировка требуют подтверждения и всегда удаляют регистрацию из `bd.txt`.

## Перезапуск

`drop_pending_updates=True` оставлен намеренно. После перезапуска старые callback-обновления удаляются, чтобы не выполнять действия по устаревшим кнопкам.

## Логирование

- `bot.log` — доступ, события группы, действия администраторов и технические ошибки;
- `KPP.log` — заявки на пропуска;
- `UK.log` — заявки на ремонт.

Логи автоматически ротируются согласно настройкам в `config.py`.
